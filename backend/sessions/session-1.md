## Размышления

- **Самая дорогая собственная ошибка сессии**: после первой явной просьбы
  «не пушить один конкретный скилл (`hw2-check`, пересказывает PDF)» я сам
  расширил это до правила «весь `.claude/` не пушим» — никто не просил
  игнорить каталог целиком. Это прямо противоречило цели домашки (критерии
  «агенты запускались» и «workflow приложен» неверифицируемы, если
  доказательства не в репозитории). Поймано промптом 23 через вопрос
  пользователя, зачем нужен этот пуш — исправлено точечным игнором только
  `hw2-check/`.
- **SPEC.md vs черновик аналитика** — не всегда было очевидно, что
  вставленный в чат текст (ALLOW/REVIEW/BLOCK-движок, антифрод-правила для
  платёжной операции) не входит в скоуп. `SPEC.md` уже прошла 5+1 раунд
  ревью через `workflows/spec-review.md` аналитика и описывает только
  сверку целостности адреса (5 сценариев §7, 3 статуса) — ALLOW/REVIEW/BLOCK
  там не упоминается вообще. Пользователь сам разрешил неоднозначность
  промптом 5/6: спека — рабочий документ, черновик — контекст, не ТЗ.
- **Архитектура сравнения (backend vs frontend)** — `SPEC.md` архитектуру
  сознательно не определяет (описывает поведение, не реализацию). Решение
  «backend сравнивает, frontend — тонкий клиент» принято не из спеки, а из
  распределения ролей команды («Разработчик: защитный модуль») — это
  явно зафиксировано как имплементационное решение, не продуктовое.
- **Три раунда внешней рецензии архитектуры** (промпты 19, 20, 22) — каждый
  раз рецензия была по существу и меняла контракт не косметически:
  направление зависимостей, DTO вместо сырых значений, Rule/Strategy на
  сценарий, явные интерфейсы `CheckRule`/`CheckResult`/`RuleResult`, границы
  транзакции, семантика 404 для отсутствующего эталона, независимость
  Агента D от реализации при сохранении права на диагностику. Без этого
  параллельный запуск A/B/D почти гарантированно разошёлся бы в
  сигнатурах — теперь единый канонический контракт зафиксирован в
  `backend-conventions` skill, агентские файлы содержат его копию для
  автономной работы (skill побеждает при расхождении).
- **Serena, spatie/laravel-data, полный idempotency-key** — сознательно не
  взяты в этот цикл: не потому что идеи плохие, а потому что ценность
  Serena — навигация по большому/чужому коду (сам ДЗ называет этот класс
  инструментов необязательным пунктом, GitNexus/Graphify), а кодовая база
  пишется с нуля; `spatie/laravel-data` не даёт выигрыша для 1–2 DTO против
  простого `readonly`-класса; полный dedup по idempotency-key не требуется
  ни SPEC.md, ни критериями оценки. Оставлено как явное решение в
  `backend-conventions`, не как забытый пункт.
- Агенты A/B/C/D и workflow `backend-review` **описаны, но ещё ни разу не
  запускались** — пункты домашки «Агенты» и «Workflow» на момент этой
  сессии спроектированы, но не продемонстрированы фактическим прогоном.
