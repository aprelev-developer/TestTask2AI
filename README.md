# ScamTest — антифрод-утилита для криптоплатёжных страниц

Продукт: локальная тестовая страница оплаты + сервис, который сверяет
показанные пользователю данные (адрес/сумма/сеть) с тем, что реально зашито
в QR-коде, копируется по кнопке и подключено на странице, и предупреждает о
технической подмене до перевода средств. ДЗ №2, работа ведётся командой из
3 человек.

Этот файл — общая инструкция по проекту. Подробности по отдельным частям
находятся в `backend/README.md` и `frontend/README.md`.

## Что нужно установить

- **Docker Desktop** — backend целиком запускается в контейнерах, локально
  ставить PHP/Composer/Postgres не нужно.
  - **macOS**: `brew install --cask docker`, либо скачать с
    https://www.docker.com/products/docker-desktop — после установки
    запустить приложение Docker Desktop один раз (иконка кита в трее),
    дождаться статуса «Running».
  - **Windows**: скачать установщик с https://www.docker.com/products/docker-desktop,
    потребуется WSL2 (установщик сам предложит его включить, если ещё
    нет) — после установки перезагрузить и запустить Docker Desktop.
  - **Linux**: `curl -fsSL https://get.docker.com | sh` (Docker Engine) +
    `sudo apt install docker-compose-plugin` (или аналог для вашего
    дистрибутива) — либо через официальную инструкцию
    https://docs.docker.com/engine/install/.
  - Проверить, что всё установлено: `docker compose version` должен
    вывести версию, а не ошибку «command not found».
- **Node.js 24+ и npm** — для frontend.
- **Git** — для клонирования репозитория.

PHP, Composer и PostgreSQL локально устанавливать не нужно: backend работает
в Docker.

## Как поднять backend

Команды запускаются **из корня репозитория** — `cd backend` не нужен,
`Makefile` в корне сам передаёт команду в `backend/`:

```bash
cp backend/.env.example backend/.env   # если .env ещё нет — переменные уже настроены под Docker
make up
```

`make up` собирает образ (PHP 8.2 + расширения под Postgres) **без вывода
трейса сборки** (чтобы не заваливать терминал стеной строк — если сборка
всё же упадёт, ошибка всё равно покажется), поднимает Postgres, дожидается
его готовности и **сам прогоняет миграции и сидирует демо-данные** —
больше никаких ручных шагов не нужно. Первый запуск займёт минуту-две
(сборка образа), дальше — секунды.

Backend слушает **`http://localhost:8000`**.

Проверить, что поднялось:

```bash
curl -i http://localhost:8000/up   # ожидаем 200
```

Если порт 8000 занят чем-то другим — поменяйте `APP_PORT` в `backend/.env`
и пересоберите (`make up`).

### Остальные команды (все — из корня репозитория)

| Команда | Что делает |
|---|---|
| `make up` | Поднять всё (backend + Postgres), с автомиграциями и сидом |
| `make down` | Остановить и удалить контейнеры (данные БД в volume сохраняются) |
| `make logs` | Логи обоих сервисов |
| `make test` | Прогнать полный backend-набор: 58 тестов / 192 assertions |
| `make sh` | Шелл внутри контейнера backend |
| `make db-sh` | `psql` внутри контейнера БД |

Полный список и детали — `backend/README.md`.

## Что нужно знать про API

**Три эндпоинта**: два — на создание/получение тестового запуска, один —
собственно проверка. Полная интерактивная документация (Swagger UI, можно
прямо оттуда отправлять тестовые запросы) —
**http://localhost:8000/api/documentation** после `make up`.

### Шаг 1 — получить `run_id` и эталонные данные для отрисовки страницы

Прежде чем показывать тестовую страницу оплаты, нужно узнать, какой
адрес/сумму/сеть на ней рисовать. Для этого:

**`POST /api/reference-payments`** — создаёт новый тестовый запуск. Тело —
все поля опциональны, что не передали — backend сгенерирует сам (явно
фиктивное значение, не похожее на настоящий реальный адрес):

```bash
curl -s -X POST http://localhost:8000/api/reference-payments \
  -H "Content-Type: application/json" -d '{}'
# → {"run_id":"...", "address":"test-addr-...", "amount":"...", "network":"BTC", "allowed_scripts":[...]}
```

Можно передать любые поля явно (например, зафиксировать `network` или свой
`address` для конкретного сценария теста), остальное всё равно сгенерируется:

```bash
curl -s -X POST http://localhost:8000/api/reference-payments \
  -H "Content-Type: application/json" -d '{"network": "ETH"}'
```

**`GET /api/reference-payments/{run_id}`** — получить те же данные снова
позже (тот же формат ответа, `404` если `run_id` не существует). Полезно,
если страницу нужно перезагрузить, не создавая новый запуск.

Для быстрого старта без создания своего запуска — есть готовая демо-запись,
см. ниже.

### Шаг 2 — отправить проверку

**`POST /api/checks`**, тот же `run_id`, что получили на шаге 1.

#### Что отправлять

Все значения, которые фронтенд «увидел» на тестовой странице — сырые,
без собственной предобработки (backend сам решает, подмена это или нет):

```json
{
  "run_id": "11111111-1111-1111-1111-111111111111",
  "displayed_address": "адрес, показанный на странице",
  "displayed_amount": "сумма, показанная на странице (строка!)",
  "displayed_network": "сеть, показанная на странице",
  "qr_address": "адрес, декодированный из QR — null, если декодировать не удалось",
  "qr_amount": "сумма из QR — null, если не удалось",
  "qr_network": "сеть из QR — null, если не удалось",
  "copy_button_value": "что реально скопировалось по кнопке «Копировать» — null, если кнопку не нажимали/не проверяли",
  "address_after_watch_window": "адрес на странице через 5 секунд после старта проверки — null, если не проверялось",
  "page_scripts": ["список src всех <script> на странице"] 
}
```

**Важно**: `null` в опциональном поле — это не «пусто», это «не удалось
технически проверить этот пункт». Не подставляйте туда предыдущее
известное значение и не пытайтесь угадать — backend сам корректно обработает
`null` как «сценарий проверить не удалось» (`incomplete_checks`).

`run_id` — идентификатор конкретного запуска теста; под него на backend
уже должны быть заведены эталонные данные (`reference_payments`) — для
демо есть готовая запись, см. ниже.

#### Что приходит в ответ

```json
{
  "result": "Обнаружена подмена",
  "triggered_scenarios": ["7.1"],
  "details": [{"scenario": "7.1", "expected": "...", "actual": "..."}],
  "incomplete_checks": [],
  "incomplete_message": null
}
```

- `result` — одна из трёх строк: `"Подмена не обнаружена"`,
  `"Есть подозрение"`, `"Обнаружена подмена"`, **или `null`**, если ничего
  не сработало, но что-то не удалось технически проверить (см.
  `incomplete_message` ниже) — по SPEC.md в этом случае «Подмена не
  обнаружена» показывать нельзя.
- `triggered_scenarios` — какие из сценариев 7.1–7.5 сработали (может быть
  несколько сразу).
- `details` — по каждому сработавшему сценарию: что ожидалось и что
  увидели на самом деле, показывайте это пользователю рядом с
  предупреждением.
- `incomplete_checks` — какие сценарии не удалось технически проверить.
- `incomplete_message` — точный текст `"Проверка выполнена не полностью"`,
  если `incomplete_checks` не пуст, иначе `null`. Показывайте этот текст
  как есть, не составляйте свой — источник истины он один, здесь.

#### Коды ошибок

- **`422`** — тело запроса не прошло валидацию:
  `{"error": {"message": "...", "fields": {"поле": ["текст ошибки"]}}}`.
- **`404`** — `run_id` синтаксически валиден, но эталонных данных под него
  нет: `{"error": {"message": "..."}}` (без `fields`).

### Готовая демо-запись для тестирования интеграции

После `make up` в базе уже есть эталон с
`run_id = 11111111-1111-1111-1111-111111111111`, адрес `addr-real`, сумма
`1.00000000`, сеть `BTC`, разрешённый скрипт
`https://payments.example/checkout.js` — им можно пользоваться сразу, не
создавая свои данные. Готовые примеры `curl` под все три статуса и 404 —
в `backend/README.md` → «API — примеры curl».

## Если что-то не работает

- `docker compose version` выдаёт ошибку → Docker не установлен или не
  запущен — см. раздел «Что нужно установить» выше.
- `make up` падает на сборке → `make down` (или `docker compose down -v`
  для полного сброса, включая БД) и попробовать `make up` заново.
- Порт 8000 занят → поменять `APP_PORT` в `backend/.env`.
- Ответ `/api/checks` не совпадает с этой инструкцией → сверьтесь со
  Swagger (http://localhost:8000/api/documentation) — это сгенерировано
  из актуального кода и не может разойтись с реальным поведением; если и
  тогда не сходится — это баг, сообщите автору backend.
